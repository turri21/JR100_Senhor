# 命令境界トレース形式 v1

Python参照実装（pyjr100emu `debug_runner --trace`)とVerilatorハーネスが共通で出力するテキスト形式。`tools/trace_diff.py` が比較する。記録項目は要件定義書（AGENTS.md）§5.2 に従う。

## 全体構造

- UTF-8 テキスト、1行1レコード、改行は LF
- `#` で始まる行はメタデータ/コメントで、比較対象外（生成元・プログラム名などの記録を推奨）
- 状態レコードは `S ` で始まる1行

## サンプリング境界

サンプルは「CPUが次のオペコードをフェッチする直前」の境界ごとに1件出力する。

- 通常命令の完了直後（= 次命令フェッチ直前）
- 割込みエントリ（レジスタ退避とベクタ読込）の完了直後
- WAI 待機中の各クロック

Python版は `computer.tick(1)` の呼び出し1回ごとに1サンプルを出力し、この規則と一致する。`n` は1始まりのサンプル番号で、割込み・WAIの無い区間では実行済み命令数と一致する。

## Sレコード

固定順の `key=value` を空白1個で区切る。16進は大文字・固定幅（`%02X`/`%04X`）、10進は幅なし。

```
S n=<dec> clk=<dec> pc=%04X a=%02X b=%02X ix=%04X sp=%04X cc=%02X ora=%02X orb=%02X ddra=%02X ddrb=%02X acr=%02X pcr=%02X ifr=%02X ier=%02X sr=%02X t1=%04X t1l=%04X t2=%04X t2l=%04X
```

- `clk`: リセット起点の累積クロック
- `cc`: CCRバイト。`0xC0 | H(0x20) | I(0x10) | N(0x08) | Z(0x04) | V(0x02) | C(0x01)`
- `t1`/`t2`: Timer 1/2 のカウンタ現在値、`t1l`/`t2l`: ラッチ値（いずれも16bitマスク）
- VIA値は JR100 の R6522 内部状態を読み出す（IFR bit7 を含む生の IFR）

## メモリ

メモリ範囲は従来どおり実行終了後のダンプ（`--dump`/`--dump-range`、hex形式）で記録し、`trace_diff.py` がダンプ同士を別途比較する。

## 比較規則（trace_diff）

- `#` 行を除き、S行を先頭から順に突き合わせる
- 最初に異なる行で停止し、行番号・`n`・相違フィールドの一覧を報告する
- 一方だけ先に終端した場合も差分として報告する
- メモリダンプ（hex形式）はアドレス単位で比較する
- 差分なしなら終了コード0、差分ありなら1、入力不正は2
